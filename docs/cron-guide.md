# 邮件发送频率配置指南

本工具通过 GitHub Actions 的定时任务（cron）来控制邮件发送频率。你需要同时完成两件事：

1. **修改 `.github/workflows/main.yml` 中的 cron 表达式**（控制工作流触发时间）
2. **在 `CUSTOM_CONFIG` 中设置 `executor.retrieval_days`**（控制每次检索的时间范围）

---

## 第一步：修改 cron 表达式

打开 `.github/workflows/main.yml`，找到以下片段：

```yaml
on:
  workflow_dispatch:
  schedule:
    - cron: '0 22 * * *'   # ← 修改这一行
```

cron 表达式格式为：`分 时 日 月 周`，时区为 **UTC**（北京时间 = UTC+8，即北京时间 22:00 对应 UTC 14:00）。

### 常用场景对照表

| 需求 | cron 表达式 | 说明 |
|---|---|---|
| 每天北京时间 22:00 | `0 14 * * *` | UTC 14:00 = 北京 22:00 |
| 每周一北京时间 22:00 | `0 14 * * 1` | 每周一 |
| 每周三北京时间 22:00 | `0 14 * * 3` | 每周三 |
| 每3天北京时间 22:00 | `0 14 */3 * *` | 每隔3天 |
| 每7天北京时间 22:00 | `0 14 */7 * *` | 每隔7天 |
| 每月1号北京时间 22:00 | `0 14 1 * *` | 每月1号 |

> **注意**：`*/N` 语法是从每月1号起步计算，并非从第一次运行起步，因此 `*/7` 不等于"7天后第一次运行"，而是每月的 1、8、15、22、29 号触发。如需精确的"每N天"，推荐直接写明具体日期，或使用每周触发（`* * * * 1` = 每周一）。

---

## 第二步：在 CUSTOM_CONFIG 中设置检索范围

在你的 GitHub 仓库 → Settings → Variables → `CUSTOM_CONFIG` 中，添加以下配置：

```yaml
executor:
  retrieval_days: 7   # 检索近7天的论文（与发送间隔对齐）
```

### `retrieval_days` 与发送间隔的推荐搭配

| 发送频率 | 推荐 `retrieval_days` |
|---|---|
| 每天 | `1` |
| 每3天 | `3` |
| 每周 | `7` |
| 每两周 | `14` |
| 每月 | `30` |

> **提示**：`retrieval_days` 可以大于发送间隔（例如每周发送但检索近10天），这样可以避免因节假日/arXiv停更导致某些日期没有论文的问题，但会产生少量重复。

---

## 完整示例：每周一发送，检索近7天

**`.github/workflows/main.yml`**：
```yaml
schedule:
  - cron: '0 14 * * 1'   # 每周一北京时间22:00
```

**`CUSTOM_CONFIG`**：
```yaml
executor:
  retrieval_days: 7
  send_interval_days: 7   # 仅作记录，不影响运行逻辑
```
